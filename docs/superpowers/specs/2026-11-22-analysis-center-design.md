# 统一分析中心设计（第一阶段：选股预测族）

> 状态：已确认（2026-11-22）。目标：把"选股预测"族的多个工具合并为一个入口、一个引擎；
> 回测族、市场资讯族在后续阶段按同样模式推进。

## 背景与问题

应用内选股预测相关工具入口分散、能力重叠：

| 现入口 | 路由 | 实质 |
|---|---|---|
| K线分析 | `/kline-analysis` | 单股技术分析 |
| 选股工作台 | `/analysis/workbench` | Tab 容器（形态/策略筛选，自有引擎） |
| 每日选股 | `/daily-pick` | DailyPick 引擎（扫描+评分+Kronos 因子） |
| 狩猎场 | `/khunter` | 观察→确认→退出 全链路（时点约束/数据闸门/风险过滤） |
| 股票推荐 | `/research/recommends` | AI 推荐列表（挂在"研究资讯"组） |

Kronos（AI 价格预测）集成现状不合理：

1. 预测接口挂在 `TradingRecordHandler`（交易记录处理器）名下，归属错误；
2. "AI 预测"点击后模型冷启动需 30 秒以上，超时无回显；
3. 作为评分因子只跑 top30、权重 0.05 硬编码，预测内容不可见、影响不可解释；
4. 预测只画在 K 线图上，与选股/狩猎场没有闭环。

## 目标形态

统一分析中心：单页 Tab 容器，一个选股引擎，Kronos 作为统一预测服务。

**非目标（第一阶段）**：选股工作台（ScreeningWorkbench）自有筛选引擎不合并，仅作为 Tab 嵌入；
回测族、市场资讯族不做；daily_pick 旧接口删除留给下一阶段。

## 架构与组件

### 后端

- **统一选股引擎 = khunter 流水线**（既有：点入时点扫描 → 五维评分 → 数据闸门 →
  观察 → 风险过滤 → 同步就绪确认 → 入场 → 退出），本次不做引擎级行为改动。
- **并入 DailyPick 的差异化能力**：
  - Kronos 预测因子：由 `daily_pick_kronos.go` 的内部模块改为评分引擎的可配置维度
    （服务不可用 → 中性分 + degraded 标记，不阻塞主链）；
  - 权重配置：`config/khunter_technical_weights.json`（既有 overrides 机制）吸收
    daily pick 权重项，只留这一个权重配置入口；
  - 排名/复盘：复盘对应 khunter 既有 RiskHistory/轨迹；排名为观察列表的排序视图，
    不另建引擎。
- **新增 `AnalysisCenterService` 门面**：统一暴露 运行 / 观察 / 推荐 / 预测 / 状态
  接口，内部委托 khunter 引擎与 Kronos 客户端；Kronos 预测接口从
  `TradingRecordHandler` 迁入本门面。
- **旧 daily_pick handler 保留为兼容壳**：内部转调 `AnalysisCenterService`，
  响应格式不变，标记 deprecated，下一阶段删除。

### 前端

- 新建 `/analysis`（分析中心）单页 Tab 容器，Tab 顺序按使用频率：
  **推荐 | 狩猎场 | 选股工作台 | K线分析**。
- Tab 内嵌现有组件：KhunterPanel / ScreeningWorkbench / K线分析组件原样嵌入
  （keep-alive 缓存状态）；`DailyPickPanel` 改造为"推荐"视图，数据源切到门面服务。
- 左侧菜单"分析工具"组收敛为 1 项"分析中心"；旧路由 301 重定向到对应 Tab
  （沿用现有 `/analysis/pattern` 重定向先例）；`/research/recommends` 保留，
  但从菜单隐藏（在分析中心内可达）。

## Kronos 统一集成

定位：统一预测服务（后端托管生命周期），三个消费面：

1. **单股预测（交互面）**：推荐视图、狩猎场观察、K线分析的上下文均可发起。
   - 异步任务化：点击后先返回"模型加载中"任务 ID，后端就绪后推送结果
     （解决冷启动 30s 超时无回显）；同日同参数命中缓存直接返回；
   - 结果叠加显示在 K 线图上（现有能力保留）。
2. **批量因子（评分面）**：每日扫描后对观察候选 top N 批量预测，作为评分可配置
   维度；权重进配置（Kronos 段：开关/topN/predLen/权重/lazy start）；
   **预测明细落库**，推荐视图里每只候选可展开预测曲线与因子贡献（黑盒变透明）。
3. **滚动回测（验证面）**：既有 `kronos_rolling_backtest` 提升为分析中心
   "预测质量"页，支撑因子启停与权重决策。

服务治理：生命周期归后端（按需拉起 + 健康检查 + 状态徽标，lazy start 设置保留）；
服务离线时交互面提示"预测服务离线"，评分面降级中性分 + degraded 标记。

## 数据流

```
15:30 收盘同步就绪
  → khunter 扫描（形态策略 + 五维评分，技术权重来自统一配置）
  → Kronos 批量预测（观察候选 top N，异步、可降级）
  → 因子并入评分 → 数据闸门 → 观察落库
T+1~T+3 → 同步就绪确认 → 入场 → 持仓/退出
推荐视图 = 观察中的高分候选（评分 + Kronos 预测摘要，可展开明细）
```

- `daily_pick` 结果表停止写入，历史数据保留只读；新链路写 khunter 表（幂等 upsert 既有）。
- 权重配置收敛：`khunter_technical_weights.json` 吸收 daily pick 权重项；
  Kronos 因子配置独立成段（开关/topN/predLen/权重/lazy start）。

## 错误处理

| 故障 | 行为 |
|---|---|
| Kronos 服务离线/冷启动中 | 交互面：任务挂起 + 状态提示；评分面：中性分 + degraded 标记，主链不阻塞 |
| Kronos 预测结果异常（缺字段/空） | 该候选因子记缺失原因，不混入评分 |
| 批量预测部分候选失败 | 成功部分照常落库，失败列表进运行汇总 message |
| 旧接口兼容壳转调失败 | 返回原格式错误，旧视图不受新链路故障波及 |
| 同步未就绪（既有） | 盘中只观察不确认（不变） |

## 测试策略

- 引擎：Kronos 因子混入/降级单测（mock 服务客户端）；评分权重配置合并回归；
- 门面：旧 daily_pick 接口契约测试（转调后响应字段一致）；分析中心聚合接口单测；
- 异步预测：任务登记→就绪推送的时序测试（模拟冷启动）；
- 前端：Tab 容器 + 推荐视图切换的 node:test 组件测试（沿用现有测试基建）；
- 端到端：沿用 `khunterreplay` 回放 CLI 验证合并后评分口径不漂移（五案例对照）。

## 阶段划分

- **第一阶段（本设计）**：选股预测族统一分析中心 + Kronos 统一集成。
- 第二阶段：回测族（旧信号级回测 / 四组对照 / AI 推荐回测 → 回测中心）。
- 第三阶段：市场资讯族。选股工作台筛选引擎是否并入统一引擎，视第一阶段使用情况再定。
