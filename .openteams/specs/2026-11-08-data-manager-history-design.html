数据管理：历史 K 线分页搜索与同步状态优化

日期：2026-11-08 · 范围：桌面端数据管理页面及其查询接口

目标是在不改动同步执行、断点与重试逻辑的前提下，让历史 K 线可检索、可分页，并让同步进度更清晰、及时。

1. 方案与边界

采用

服务端 SQL 分页，使用 Count + Order + Offset/Limit。将当前“个股数据浏览”替换为“历史 K 线数据”，避免同一页面出现两个易混淆的数据表。

不做

不全量加载后前端分页；不新增股票基础信息浏览区；不调整同步 Worker、缺口修复、断点、复权或重试行为。

2. 历史 K 线数据

  • 默认按交易日期倒序展示，并使用稳定的次级排序避免翻页重复或遗漏。
  • 每页默认 20 条，可切换 20、50、100 条；页码、总条数和总页数来自后端响应。
  • 一个关键词输入框支持股票代码或名称搜索；提交搜索和改变每页条数时回到第 1 页。
  • 表格列：股票代码、股票名称、交易日期、周期、复权、开盘、最高、最低、收盘、成交量、成交额。
  • 代码条件复用 stockcode.StockCodeCandidates 与现有周期候选规则，兼容数据库中的历史混合格式。
  • 名称搜索先通过 AllStockInfo 找到匹配股票代码，经 stockcode.Normalize 和 StockCodeCandidates 转换后查询 K 线；代码搜索与名称搜索使用同一套候选代码规则。

DataManager.vue → api/backtest.ts → 手工 Wails 绑定 → backtest.Service → KLineStore 分页查询 → kline_bars

3. 同步状态

区域行为
状态汇总展示待同步、进行中、已完成、失败、部分完成的数量；汇总来自数据库，而非仅统计当前表格行。
任务明细英文状态映射为中文标签；数字进度改为带百分比的进度条；失败原因可查看，避免长文本撑坏布局。
刷新进入页面、启动同步后立即刷新；存在进行中任务时每 5 秒轮询，离开后清理；保留手动刷新按钮。
缓存统计同步进度刷新后联动更新缓存统计，使总 K 线数、股票数和日期范围保持接近实时。

4. 接口与组件

  • KLineStore 新增分页查询，不把现有全量 QueryKLines 结果放入内存分页。
  • backtest.Service 暴露历史 K 线分页查询；响应沿用 list/total/page/pageSize/totalPages 结构。
  • 调整 GetSyncProgress 返回 summary/tasks：汇总由数据库分组统计，任务明细保留现有活动任务及最近完成任务语义，页面表格固定高度滚动。
  • 同步更新 Service.js、Service.d.ts、models.ts 与 src/api/backtest.ts，遵守项目 -skipbindings 构建约定。
  • DataManager.vue 复用现有 Naive UI 表格、分页、标签和进度条模式。

5. 异常与空状态

  • 查询失败时提示错误并保留当前已展示数据，避免翻页失败清空页面。
  • 无匹配结果时显示明确空状态；空关键词表示浏览全部历史 K 线。
  • 页码或每页条数统一在后端限制合法范围，防止负数偏移和超大查询。
  • 轮询失败不清空同步状态；后续活动轮询或手动刷新可恢复。

6. 验证与交付

  1. 定向 Go 测试覆盖总数、首页/中间页/末页边界、合法化参数和混合格式代码搜索。
  2. 执行 go build ./...、go vet ./backend/... 与相关定向测试。
  3. 使用 node node_modules\vite\bin\vite.js build 构建前端。
  4. 构建并启动实际桌面程序，验证空搜索、代码/名称搜索、翻页、每页条数、启动同步、中文状态、进度条、自动刷新和离开页面停止轮询。

验收以实际页面行为和定向测试结果为准；编译通过不替代运行时验证。
