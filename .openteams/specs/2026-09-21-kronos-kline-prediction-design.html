Kronos K线预测能力集成 — 设计文档

日期：2026-09-21 ｜ 项目：go-stock ｜ 状态：已确认

一、背景与目标

交易日志的「持仓深度分析」（backend/data/holdings_deep_analysis.go + frontend/src/components/trading/HoldingsDeepAnalysisModal.vue）目前是 「静态技术指标 + 资金/板块/新闻聚合 → LLM 解读」链路，缺少前瞻性：没有对未来走势的量化推演。

参考项目：

  • Kronos（清华开源 K 线基础模型）：OHLCV 序列生成式模型，可预测未来 K 线；small 版 24.7M 参数，CPU 可运行。
  • facecat-kronos（花卷猫）：Kronos 的 Python 封装，提供预测虚K线可视化、历史回测比对、T/top_p 参数调节。

目标：将 Kronos 预测做成 go-stock 的通用可选能力——

  1. 设置页托管本地 Python 推理服务，用户一键开关，免手动命令行；
  2. 预测能力覆盖全部 K 线图（自选股、交易日志、搜索结果等），叠加预测虚K线；
  3. 持仓深度分析同步集成预测数据并注入 LLM prompt；
  4. 提供回测比对功能，帮助用户评估预测可信度。

非目标：不做模型微调训练；不做分时级别预测（仅日线起步）；未开启功能时现有流程零改动。

二、架构总览

┌─ go-stock (Go + Wails) ────────────────────────┐      ┌─ kronos_service (Python FastAPI) ──────┐
│ 设置页 KronosConfig ─→ KronosProcessManager     │ HTTP │ POST /health   存活探测                │
│                        (拉起/心跳/退出回收)      │─────→│ POST /predict  单只预测                │
│ KronosClient ─→ handler.PredictKLine(code,...)  │      │ KronosPredictor(small/base, cpu/cuda)  │
│ K线图组件「AI预测」开关 → 预测虚K线叠加           │      │ 模型: HuggingFace 镜像 / 本地 model 目录│
│ holdings_deep_analysis.go 预测注入 prompt       │      └────────────────────────────────────────┘
└────────────────────────────────────────────────┘

Python 服务随仓库提供（python/kronos_service/，单文件 FastAPI + requirements.txt）。 go-stock 只通过 HTTP 127.0.0.1 通信，未开启时对现有功能零影响。

三、组件设计

① 设置页「Kronos 预测」配置区

配置项默认值说明

惰性启动开首次调用预测时自动拉起服务

附：状态指示灯（绿=在线 / 灰=未启动 / 红=异常）+「启动/停止」按钮 +「一键初始化」（创建 venv → pip 安装依赖（清华镜像）→ HF 镜像下载模型，进度展示）。配置持久化到现有设置存储。

② KronosProcessManager（Go）

  • 以子进程方式启动 Python 服务，工作目录为 python/kronos_service/；
  • /health 心跳：3 秒超时，启动后最多等 120 秒进入在线态（首次加载模型慢）；心跳连续失败自动重启一次；
  • 主程序退出时回收子进程（防孤儿进程）。

③ KronosClient + PredictKLine（Go handler）

PredictKLine(stockCode string, period string, predLen int) → {
  bars:     [{date, open, high, low, close, volume}],   // 预测的未来K线
  summary:  { lastClose, predHigh, predLow, direction, confidence }
}
  • 内部复用 datasource.GetRouter().GetKLine 取日K（lookback 120，代码经 normalizeTradingRecordAPI 规范化）；
  • confidence 由多次采样收盘价的离散度换算（离散度越小置信度越高）；
  • 错误返回结构化错误码：SERVICE_OFFLINE / TIMEOUT / MODEL_MISSING / INSUFFICIENT_DATA。

④ 前端 K 线预测叠加（通用）

  • 现有 K 线图组件（frontend/src/components/kline/）增加「AI 预测」开关；
  • 开启后调用 PredictKLine，在真实 K 线右侧渲染半透明虚K线 + 竖向分隔线（样式参考 facecat），悬浮显示预测 OHLC 与置信度；
  • 功能未配置或服务离线时按钮灰显并提示前往设置页开启；
  • 自选股、交易日志、搜索等所有使用该 K 线组件的页面自动获得此能力。

⑤ 持仓深度分析集成

  • GetHoldingsDeepData 在功能开启时为每只持仓并行追加预测摘要，数据包新增 kronosForecast 字段；
  • 前端持仓卡片新增「Kronos 预测」行（方向 + 5日区间 + 置信度）；
  • BuildHoldingsDeepPrompt 注入预测数据，并要求 LLM 结合预测给出操作结论；
  • 服务离线时自动降级为现状，不报错、不阻塞。

⑥ 回测比对（可选入口）

  • 预测面板提供「回测验证」：以历史 T-10 日为切点生成预测，与 T-10..T 真实走势对照；
  • 展示：方向对错、收盘价平均偏差，辅助判断当前预测可信度。

四、数据流与错误处理

  • 所有调用统一经 KronosClient，30 秒超时；失败时前端统一 toast + 状态灯变红；
  • 任何预测失败只影响预测功能本身，不阻塞行情、交易日志、持股分析主流程；
  • Python 侧对非法输入（K线不足 30 根、长期停牌）返回 4xx + reason，Go 侧转译为 INSUFFICIENT_DATA。
