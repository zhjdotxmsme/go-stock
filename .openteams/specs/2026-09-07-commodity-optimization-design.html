go-stock · 大宗商品模块 · 设计规格（Design Spec）

大宗商品模块优化

方案 B · 核心数据内嵌 + 独立信号 Tab 标准数据深度 贵金属 / 原油 / ETF 范围 日期 2026-09-07

0. 背景与现状

当前大宗商品模块（backend/data/commodity_*.go + frontend/src/components/Commodity*.vue）已具备：

  • 报价 / 多周期 K 线：现货、期货、ETF 多源回退（东财 push2/push2delay、Sina、Yahoo、WSCN）。
  • 宏观面板：美元指数、美债收益率曲线、TIPS 实际利率、盈亏平衡通胀。
  • AI 分析：基于规则模板的技术面 / 基本面 / 相关性 / 报告 + 多智能体流。

三个短板（本次要补）：

  1. 缺期货核心数据：无持仓量/增减持仓无期限结构(carry)无库存/仓单无 COT。
  2. 策略停留在单品种规则模板，无跨品种信号排行（"今天该做什么"一目了然的表）。
  3. AI 分析引用不到真实期货面数据（持仓/carry/库存）。

1. 范围决策（已确认）

决策项选择
优化方向期货核心数据补齐 ＋ 跨品种策略信号排行 ＋ AI 分析增强
明确不做（YAGNI）品种扩面（铜/铝/黑色/农产品，本轮不碰 registry）、回测引擎、信号历史快照存储、新数据源手动配置界面
数据深度标准深度：全部自动拉取；COT / 周库存拉不到即降级隐藏，不做重试风暴
落地架构方案 B：期货核心数据内嵌「行情总览」＋ 独立「策略信号」Tab ＋ AI 工具复用两者

2. 后端架构与数据层

新增 2 个文件 + 修改 2 个文件，全部沿用 package data 现有模式：

新增  backend/data/commodity_futures_panel.go   ← 期货盘面数据服务（持仓/carry/库存/COT/比值/ATR/季节性）
新增  backend/data/commodity_signal_engine.go   ← 策略信号引擎（纯计算、零网络、可单测）
修改  backend/data/tool_commodity.go            ← AI 工具喂新数据 + 注册新工具
修改  backend/handler/commodity_handler.go      ← +2 个 Wails 绑定方法

2.1 两个新 Wails 方法（一次调用取一屏，不逐品种散调）

方法返回前端用途
GetCommodityFuturesPanel() AU/AG/SC 各自持仓量+日增仓、期限结构(carry)、ATR%、金银比+分位、SHFE/COMEX 库存、COT 净持仓+占比、当前月季节性（5 年均值） 总览页新「期货盘面」卡片
GetCommoditySignalBoard() 全 11 个可交易标的信号排行表（每行 5 信号 + 综合分 + 结论） 新「策略信号」Tab

2.2 数据源优先级与降级（每项独立，任一失败只隐藏该行）

数据点主源回退降级
持仓量 / 日增仓 东财 push2 期货报价（扩 fields，主源已通） Sina nf_ 报价（现有解析路径加一个字段） 隐藏 OI 行，信号权重自动重分配
期限结构 carry 东财 clist 期货合约列表取最近两月 Sina 两合约代码 隐藏 carry 行
金银比本地计算（已有 XAUUSD/XAGUSD 报价+K线）—不会失败（历史不足则隐藏分位）
ATR / 季节性本地计算（已有日 K，≥3 年）—不会失败（历史不足则隐藏）
SHFE / COMEX 库存东财数据中心库存接口（核对 reportName，样例固化进测试）—隐藏，标注"本周未获取"
CFTC COT 净持仓CFTC 公开 JSON（每周二更新，6h TTL 缓存）—隐藏，标注不可用
TTL 缓存（进程内 map+mutex，与 TDX probe cache 同模式）：OI/carry 60s · 库存 1h · COT 6h · 季节性 24h。

3. 策略信号定义（确定性、可复现、零 AI）

5 个信号全部基于日 K + 实时盘面，后端算好前端只展示。无随机性、无 AI 介入。

信号定义取值
趋势MA20 vs MA60 交叉 ＋ 收盘价相对 MA20 位置多头 / 空头 / 过渡
动量20 日 & 60 日收益率符号与幅度分档强多头 / 多头 / 中性 / 空头 / 强空头
突破唐奇安 20 日：收盘 ≥20日高×0.99 → 多头突破；≤20日低×1.01 → 空头突破多头突破 / 区间 / 空头突破
Carry近远月价差/近月：贴水>1% 偏多；升水>1% 偏空贴水偏多 / 中性 / 升水偏空 仅期货
持仓四象限当日涨跌 × OI 日变化涨+仓增 / 涨+仓减 / 跌+仓增 / 跌+仓减 仅期货

综合分（[-1, +1]，现货/ETF 缺 OI、carry 时权重自动归一化）

趋势 0.30 · 动量 0.25 · 突破 0.20 · Carry 0.15 · 持仓 0.10

输出行结构

{ code, name, market(纽约/伦敦/上海),
  trend, momentum, breakout, carry, oiQuad,
  score, verdict(偏多/中性/偏空) }

金银比分位、库存周变动、COT 占比、ATR%、季节性均由面板数据接口算好，前端不做任何指标计算；ATR/季节性历史不足则整行隐藏。

4.2 新 Tab「策略信号」（CommoditySignals.vue，commodity.vue 第 3 个 tab）

  • 全品种排行表（n-table）：品种 | 市场 | 趋势 | 动量 | 突破 | Carry | 持仓象限 | 综合分(±1 横向色条) | 结论标签，按 |score| 降序排序，红多 绿空（同应用"红涨绿跌"惯例）。
  • 顶部一行"市场概览统计"：偏多 X / 中性 Y / 偏空 Z。
  • 点击行 → 总览页切到该品种 K 线（复用现有 selectAsset 通路）。
  • 降级：接口返回 failedSignals 时对应列表头标灰 + tooltip "数据源暂不可用"。

4.3 AI 分析增强（tool_commodity.go，不动现有 4 工具签名，只扩返回字段）

工具新增内容
GetCommodityTechnicals+ OI 四象限、Carry 状态（期货标的）
GetCommodityFundamentals+ 金银比+分位、库存变动、COT 净持仓
GetCorrelationAnalysis不改动（已有比值分位）
新 GetCommoditySignalBoardAI 直接引用全品种信号排行，给出"哪个方向拥挤、哪个有 carry"结论
待核对：NewCommodityAnalysisStream 的 tool 列表若为白名单制，需把新工具加进白名单（实现时查 agent prompt 组装处，一处小改）。

构建交付（既定流程）

  1. go build ./... + go vet ./backend/... 通过。
  2. Node 24 + Vite 重打 dist（验证新组件在 bundle 里）。
  3. exe 重建到 E:\open-source\ai\go-stock\build\bin\go-stock.exe，-tags desktop,production。
  4. 用户点启动 → 抽查：期货盘面卡数值 vs 东财网页、信号表方向红绿、AI 分析一次引用新数据的对话。
