持仓股票技术指标与 AI 每日总结

交易日志页增强 · 设计文档 · 2026-09-17

1. 背景与目标

交易日志页（TradingRecordManager.vue）目前只展示持仓的汇总数字（成本、市值、收益）。目标是为持仓股票增加：

  • 技术指标：逐行按钮，弹窗展示该股全套技术指标（MACD/RSI/KDJ/BOLL/均线等）数值与文字解读；
  • AI 每日总结：页面级按钮，点击后对全部持仓做组合级单次 AI 分析，生成详细丰富、带总结性观点的当日总结；
  • 历史总结：列表可点击查看以往每天的总结全文与当时的持仓快照。

已确认AI 粒度 = 组合级单次总结；已确认仅手动触发（当天已生成可重新生成覆盖）；按钮位置 = 技术指标逐行 + AI 分析页面级。

2. 范围

  • 做：持仓明细 FIFO 推算接口、单股技术指标接口、AI 流式总结接口（生成完自动落库）、总结历史列表/详情、三个前端弹窗。
  • 不做（本期非目标）：收盘后定时自动总结、每股单独深度分析、总结的编辑/删除 UI、推送通知。

3. 方案选型

方案结论
A. TradingRecordHandler 加专用接口 + 独立总结表采用。FIFO 逻辑已在 trading service，扩展成逐股明细最自然；AI 流式复用成熟的 SummaryStockNews 自定义事件名模式；独立表按天存总结+持仓快照，历史查询干净。
B. 复用 ai_response_result + 多智能体引擎否。多智能体面向单股深挖，做组合总结慢且贵；魔法标记值过滤历史，快照无处放。
C. 前端组装一切否。FIFO 要在前端重写，prompt 散落前端，历史管理混乱。

4. 架构与数据流

点击「AI分析」
  └─ SummarizeHoldings(aiConfigId, eventName)        [TradingRecordHandler]
       ├─ svc.GetHoldingsDetail(ctx)                 [trading service，FIFO+priceFn 现价]
       │    └─ 每股 GetTechnicalIndicators → GetIndicatorSummary 文字摘要   [data]
       ├─ 组装详细 prompt（持仓明细 + 指标摘要 + 输出结构要求）
       ├─ openai_stream 流式 channel → goroutine EventsEmit(eventName, msg)
       │    └─ 前端 MdPreview 增量渲染，收到 "DONE" 结束
       └─ 流结束时落库 HoldingsDailySummary（同日覆盖）→ 再发 "DONE"

点击行内「技术指标」
  └─ GetStockTechnicalIndicators(code) → 全套指标数值 + 文字解读 → 弹窗展示

5. 后端接口设计（挂在现有 TradingRecordHandler，无需改 main.go Bind）

5.1 持仓明细

GetHoldingsDetail() ([]data.HoldingsPosition, error) — trading service 新增 GetHoldingsDetail(ctx)：复用现有 FIFO 循环（service.go:141-189），逐股输出 代码/名称/持仓量/成本均价/成本额/现价(priceFn)/市值/盈亏额/盈亏率。

5.2 技术指标

GetStockTechnicalIndicators(code) (*data.IndicatorResult, summary, error) — data 层新增公共封装（内部做代码规范化），调 GetTechnicalIndicators(ctx, code, "101", 60) + GetIndicatorSummary。

5.3 AI 总结

  • SummarizeHoldings(aiConfigId int, eventName string) error — 组装 prompt（要求：整体概述 → 每股一段技术面解读与短期观点 → 组合总结性观点：仓位评价/风险点/明日关注/操作建议），流式推送，结束落库后发 DONE；
  • AbortSummarizeHoldings(eventName) — 中断，不落库；
  • GetHoldingsSummaryList(page, pageSize) / GetHoldingsSummaryDetail(id)。

6. 数据模型

// backend/models/models.go，注册进 backend/db/chat_memory.go 的 AutoMigrate
type HoldingsDailySummary struct {
    gorm.Model
    SummaryDate      string  `gorm:"index;unique"` // yyyy-MM-dd，一天一份
    Content          string  `gorm:"type:text"`    // AI 总结全文 markdown
    ModelName        string                        // 使用的 AI 模型
    HoldingsSnapshot string  `gorm:"type:text"`    // 生成时持仓明细 JSON（回放用）
    StockCount       int64
    TotalProfit      float64
    ProfitRate       float64
}
func (HoldingsDailySummary) TableName() string { return "holdings_daily_summaries" }

保存策略：按 SummaryDate upsert，重新生成覆盖当天记录。

7. 前端交互设计（TradingRecordManager.vue + 三个子组件）

  • 顶部统计区右侧加「AI 分析」「历史总结」按钮；表格「操作」列前加「技术指标」按钮（逐行）。
  • AI 分析弹窗（trading/HoldingsAiSummaryModal.vue）：打开先查当天是否已有总结（有则直接展示 + 可重新生成）；生成中 MdPreview 流式渲染 + 中断按钮；AI 配置下拉仿 market.vue（系统设置取列表，默认第一条）。事件名固定 tradingHoldingsSummary，弹窗关闭即 EventsOff。
  • 技术指标弹窗（trading/StockIndicatorsModal.vue）：指标数值表 + 文字解读（MdPreview）。
  • 历史总结弹窗（trading/HoldingsSummaryHistoryModal.vue）：日期/股票数/收益率/摘要列表 → 点击进详情（全文 + 当时持仓快照表格）。
  • API 包装统一加到 frontend/src/api/trade.ts（callApi 模式）。

8. 错误处理

  • 无持仓：点「AI 分析」直接 message 提示并返回，不发起 AI 调用；
  • 个别股指标获取失败：prompt 中标注"该股指标获取失败"，不阻塞整体总结；
  • 未配置 AI：弹窗内提示前往设置页配置；
  • 流中断/网络断：Abort 不落库，前端提示；生成中关闭弹窗自动 Abort。
